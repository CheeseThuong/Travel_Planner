# ADR0034 — Separate, permission-attested community contributions

2026-10-30. SI03-01/02, additive Smart Discovery scope authorized by the user after G4 approval.

Store contributions separately from editorial places/profiles. Payload includes original user title/description/address, independently confirmed pin, canonical categories/tags and suggested duration, an access constraint and explicit rights confirmation. Never store restricted provider data, raw Maps URLs, keys or inferred verified hours/prices. A submission is not evidence of venue accuracy. Public projection always identifies community/user source and unknown hours, prices and access.

Use a dedicated NOLOGIN/NOINHERIT/NOBYPASSRLS transaction role and fixed-search-path functions, following the existing owner-store pattern without expanding trip-writer rights. All owner/moderation mutations derive UID from verified database Auth context, validate bounds/keys/types and use version checks. Authenticated clients have own/moderator SELECT via RLS but no direct INSERT/UPDATE/DELETE. Moderator membership is a private admin-managed table; user_metadata is never authorization. Public bounded RPC returns only approved, selected safe columns, never private ownership, notes, idempotency or audit.

Submit with UUID idempotency key, per-owner advisory serialization and original canonical payload fingerprint. Exact retries return existing record; reused key with different payload conflicts. Limits are five newly created submissions per rolling24h and20 non-withdrawn submissions per owner. Same-owner identical payload is a duplicate response without another row. Duplicate hints refer only to currently public editorial/community identities, are conservative, bounded and never auto-merge or leak private submissions. Moderators must enter a review note before approval; this is administrative review, not a claim that entrance/hours/prices are verified.

State transitions: submitted→verification→approved, moderator reject from submitted/verification/approved, moderator restore rejected→verification. Owner withdraw hides any state immediately; owner restore rejected/withdrawn→submitted needs fresh review. Every successful transition increments version and appends an immutable private audit event. Payload is immutable after submission to avoid stale approval; corrections use withdraw and a fresh submission. Withdrawal is reversible; permanent account deletion cascades private submission/audit. No moderation admin is automatically granted or seeded.

Alternatives: extend editorial table (reject, untrusted data contamination), trust client roles or private JWT metadata (reject, escalation), public raw table/view with sensitive columns (reject), auto-approve on geofence/AI (reject). Separate storage and narrow functions add code but make publication/revocation testable. Process/per-owner quotas cannot defeat anonymous identity farming; distributed abuse controls and operational moderators remain G8 requirements.

Tests cover type/bounds/permission/retention, RLS across owners/moderators/anon, direct-write denial, metadata escalation, quota, idempotency, optimistic versions, duplicate visibility, state/audit and transactional rollback. Apply/replay only guarded disposable Supabase. Rollback disables integration rather than destroying submissions. No production deployment or later gate approval.

SI03-02 security integration: server-session access cookie is HttpOnly, SameSite=Strict, scoped to contribution API and Secure on HTTPS. Every operation verifies upstream Auth; POST requires exact same origin, application/json and rejects cross-site Fetch Metadata. A real HTTP probe found Next's internal request.url uses localhost while actual Host/Origin are127.0.0.1. Compare browser Origin to the received HTTP Host with request protocol (validated authority); never trust forwarded-host headers. Tests retain cross-origin and malformed-host rejection. Production proxy/domain trust configuration still requires G8 review. `FORBIDDEN` is an additive403 error code and is included in telemetry's redacted allowlist. Temporary local diagnostic logging was removed after capture; no credentials/notes/body are logged.
