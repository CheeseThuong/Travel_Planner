# ADR-0014 — Scaffold dependency selection and UI state
Status: BLOCKED dependency selection within approved Master 6.2 stack; no technology/hosting change. Task P01-01. Reviewed 2026-10-21. Baseline stack remains accepted; unresolved security/support choices are not approved for gate completion.

## Context and decision
Manual scaffold preserves the existing repository and Phase 00 artifacts. Use Node 24 LTS (installed 24.19.0), npm 11.17.0, exact direct versions and committed lockfile. Next.js 16.4.2/React 19.3.1 are current npm stable metadata at review time; Next requires Node >=20.9.0 and accepts React ^19.0.0. Choose TypeScript 6.0.3 rather than stable 7.0.2 because typescript-eslint 8.72.0 supports >=4.8.4 <6.1.0. ESLint 9.39.5 is compatible with Next's >=9 peer range. No peer overrides or ignoreBuildErrors/ignoreDuringBuilds.

Initial install warned ESLint 9.39.5 is EOL. [Maintainer version-support page](https://eslint.org/version-support/) confirmed EOL 2026-08-06; corrective selection is ESLint 10.13.0 (MIT), accepted by Next >=9 and typescript-eslint ^8.57/^9/^10 peers. Do not retain an unsupported tool merely because peer ranges permit it. Initial warning/log retained; install updates the exact pin and lock.

Further tree inspection rejected ESLint 10 as a completed solution: `eslint-plugin-react@7.37.5` only accepts ESLint through ^9.7 and npm warned about peer override. Restore the upstream-compatible 9.39.5 tree for reproducible local checks; its EOL remains an unresolved blocker, NOT an approved final support choice. `npm audit` also found GHSA-vfj7-8cjw-p6xm through eslint-config-next -> @next/eslint-plugin-next -> fast-glob -> micromatch -> braces. [Current advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) lists no patched version, and registry latest braces is 3.0.3. No security override, audit exception, unstable canary, old Next-config downgrade or custom weakened lint replacement is approved. P01-01 remains BLOCKED until a supported compatible, non-vulnerable tree is available or an explicitly reviewed alternative retains checks. Architecture remains unchanged.

Use React Context when shared UI state is needed; do not add Zustand. TanStack Query, Supabase, Dexie, Motion/GSAP and 3D remain their later task dependencies, not installed speculatively. Test tools added separately in P01-02 with their own review.

## Security/license source review
- npm registry metadata read for exact versions, licenses, engines and peers before installation.
- [Next installation](https://nextjs.org/docs/app/getting-started/installation) and [Tailwind Next setup](https://tailwindcss.com/docs/guides/nextjs) inspected.
- [Next maintainer advisories](https://github.com/vercel/next.js/security/advisories), especially [GHSA-2464-fhr4-w9xw](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw), inspected: patched Next >=16.4.1 for that release line; verify installed sharp >=0.35.5 and current audit, rather than treating an old advisory as a full security guarantee.
- [shadcn manual integration](https://ui.shadcn.com/docs/installation/next), [official button registry](https://ui.shadcn.com/r/styles/new-york/button.json) and [MIT license](https://raw.githubusercontent.com/shadcn-ui/ui/main/LICENSE.md) inspected. Adapt small official Button source with retained MIT notice; do not install CLI/entire registry just for one component.

## Alternatives / trade-offs
create-next-app over an existing planning repository risks overwriting files; manual scaffold is reviewable. Latest TypeScript 7 conflicts with linter support; pin compatible stable 6. ESLint 10 not required despite latest tag; version 9 supported by peers. Extra state/graphics packages increase client work before features exist.

## Validation / rollback
P01-01 typecheck/lint/build without credentials; P01-02 component/route and mobile browser tests; audit and lock/license evidence before DONE. Bundle report from production output. Rollback removes only scaffold/task dependencies and restores prior task docs, preserving content research. No schema/API/security boundary changes.
