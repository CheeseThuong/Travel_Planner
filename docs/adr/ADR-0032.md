# ADR-0032 — Transient, bounded Brave discovery

Status: implementation detail under approved Smart Discovery2026-10-29. Live paid tests NOT authorized by credentials alone; default OFF.

Reviewed official [Place Search guide](https://api-dashboard.search.brave.com/documentation/services/place-search), [API reference](https://api-dashboard.search.brave.com/api-reference/web/place_search) and [terms](https://api-dashboard.search.brave.com/documentation/resources/terms-of-service) on2026-10-29. Endpoint `https://api.search.brave.com/res/v1/local/place_search`, token header, query/category phrase, location name or lat/lng, radius bias and count<=100. The reference offers no native offset/cursor; app pagination covers a bounded fetched window and discloses that results may change between requests.

Brave POI IDs are ephemeral (roughly8 hours), not durable Google Place IDs. All provider candidate content is request-only, no cache/database/export/save/AI-training corpus. Current terms allow transient operational storage; broader storage rights or third-party rights cannot be assumed. Keep provider URL/identity/license and unverified coordinate provenance separate from editorial/OSM/user data. Unknown hours/prices/access remain unknown; provider hints are not verified weekly opening hours or VND prices. Missing provider IDs can identify a candidate only within a response, never become a verified identity.

Use installed Zod and native fetch, no dependency/SDK. Reserve bounded per-instance minute/day request counters before a single outbound call; report conservative attempts after failure, not invented billing. Abort deadline and response-byte/count limits cover untrusted responses. No retry loop. Runtime OFF by default; BRAVE_API_KEY is server-only. Request limits do not replace a monetary cap/provider account budget and distributed deployment quota controls; those remain necessary before enabling live/production. No forward-IP trust or query/key logging.

No-key/provider failure uses independent local catalog; no synthetic records added to reach counts. Fixture providers are explicitly synthetic and used only in tests. Category/lodging, geography and dedup checks remain independent of provider relevance. Persisting a request-only result or pretending radius is a city boundary is rejected. Groq may later rank only independently permitted candidate data under separately reviewed inference rights, never train on search results.

Tests: request URL/header validation, malformed/overlarge bodies, coordinate/ID/category normalization, bounded window pagination, minute/day exhaustion, timeout/abort/429/5xx, missing config, no-key fallback, redaction and client/server boundaries. Rollback task-only code/config/docs; no schema or legacy data changes in this adapter task. No claim of live API behavior from fixture tests.

SD04-01 API amendment: compare at most130 candidates and report at most200 duplicate relationships, with an explicit truncated-review warning if needed. Only identical facts with the same scoped provider identity collapse; report removal counts. Conflicting identity/rights/city or normalized-name/address/proximity matches require confirmation and stay separate.150m is a heuristic similarity threshold, not verified identity. Preserve original source arrays and provider IDs; a conflicting repeated local candidate key receives an ephemeral variant suffix rather than overwriting an earlier catalog record. New response annotations are validated and reflected in generated OpenAPI.
