# ADR-0024 — No-fetch Maps import with independent editorial confirmation

Status: ACCEPTED implementation detail under the user's controlled P03 remediation request,2026-10-28. No gate waiver, live-provider or production approval.

## Context and decision

P03-03 must safely handle full/short links without a key. ADR0005 explicitly allows manual fallback without fetching; arbitrary redirect/DNS handling risks SSRF. Parse bounded HTTPS URLs with exact hosts (`google.com`, `www.google.com`, `maps.google.com`, `maps.app.goo.gl`, and `goo.gl/maps/...`) and validate redirect targets through the same parser. Reject credentials, nondefault ports, backslashes and controls before parsing. No runtime resolver follows redirects or performs network requests. Shortlinks ask for the expanded link or manual entry; they are not falsely reported resolved. DNS pinning and bounded-hop HTTP transport require a later reviewed adapter before live support.

Use a URL name/query solely as a search hint against our independent per-destination catalog. Return editorial candidate IDs/metadata with medium confidence; user confirmation is mandatory. An opaque Place ID alone remains unresolved. Do not persist or relabel Google-derived coordinates/names as user data. Manual title and coordinates are independently entered; unknown hours/access/cost remain explicit. Add an optional `editorial_place_id` to PlaceResolution so the client confirms the known independent record instead of trusting response coordinates.

The public no-fetch endpoint uses shared bounded JSON/error/request-ID contracts and a fixed per-process60-request/minute limiter. It does no DB work, consumes no paid API and trusts no forwarded IP. Multi-instance/global rate limiting remains a G8 deployment prerequisite; no claim of production abuse protection. Error/log schemas add only supported URL errors; raw request/provider data is not logged.

## Alternatives and trade-offs

Unrestricted fetch or automatic redirect handling: rejected (SSRF). Building a new DNS-pinned transport/provider integration now: deferred because manual fallback already meets no-key acceptance and live flags remain off. Inferring location from `@lat,lng` viewport or Google URL titles: rejected (inaccurate, provenance risk). Treating a search match as confirmed: rejected. A shared distributed limiter would require infrastructure and deployment choices absent from this task.

## Tests and rollback

Parser hostile-host/credential/port/control/redirect fixtures, no-fetch assertions, ambiguous and no-match catalog tests, API malformed/schema/unsafe/rate-limit/envelope tests, mobile/desktop candidate confirmation and manual fallback with duplicate/capacity checks. Revert task-only route/adapter/parser/UI/tests/contracts; no schema/data migration or dependency change.
