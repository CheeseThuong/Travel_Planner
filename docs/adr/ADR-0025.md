# ADR-0025 — Calendar-only draft validation before planning

Status: ACCEPTED corrective implementation detail under Phase03 remediation,2026-10-28.

P03-02's earlier DONE does not establish the accurate-draft G3 exit. Add the missing base, edge-day times and required selection fields to the existing TripDraft model. Validate real YYYY-MM-DD calendar dates using UTC solely as an ordinal calendar representation (never interpret these as trip instants). Enumerate1–7 dates without host timezone/DST arithmetic. Trip timezone must equal the supported destination's IANA timezone; scheduling/instant conversion for future DST destinations remains P04 work, not claimed here. Validate HH:mm and same-day arrival before departure; base coordinates must be explicitly entered, including optional temporary-base disclosure.

Use the existing TripDraft type, unknown hours/access/cost and user-entered provenance; do not invent provider data. Prepare an in-memory draft for explicit review, not a feasible itinerary or persisted trip. Preserve user selection sequence across manual/catalog inputs and filtering; required flags do not reorder. Null budget remains distinct from0. Editing invalidates the review. No schema/API change, runtime dependency or planner/owner capability is added.

Alternatives: declare G3 passed on old budget preview (rejected); add planner to infer missing times/base (rejected); introduce a timezone library for date-only enumeration (unnecessary dependency). Tests cover leap/reversed/overlong dates, times, coordinates, destination/stop identity, budget boundaries and input preservation. Rollback task changes without touching historical migrations/user data.
