# ADR-0023 — Bounded Supabase HTTP adapter for verified-owner access

## Context

P02-03 requires real anonymous sessions and a repository that operates with the caller's RLS identity. Exact `@supabase/supabase-js@2.118.0` was reviewed and installed experimentally, but strict TypeScript6 compilation failed in the package's WebAuthn declaration: `PublicKeyCredentialFuture<T>` is incompatible with the platform `PublicKeyCredential.toJSON()` return type. The same declaration is present in the official v2.118.0 source; only canary releases newer than that stable tag existed at review time. `skipLibCheck`, a node_modules patch and a canary dependency are not acceptable foundation fixes.

## Decision

Use the platform `fetch` API in a server-only adapter restricted to Supabase's documented Auth user endpoint and the exact PostgREST table/RPC paths required by the owner draft repository. Validate a bearer token with `GET /auth/v1/user` before constructing the repository. Database calls use the public publishable/anonymous key plus that caller JWT so RLS remains authoritative. Bound token length, response size, request bodies and error mapping; never forward arbitrary paths or headers.

Do not use a service-role key for owner CRUD, do not trust decoded JWT claims or client-provided owner IDs, and do not print/store access or refresh tokens in test evidence. Local integration obtains disposable local URL/key material at runtime and reports only aggregate assertions. CI does not contact a cloud Supabase project or paid provider.

## Alternatives

- Stable official SDK: preferred initially and tested, then rejected for this task because it fails the repository's strict TypeScript6 check in upstream declarations.
- Patch the SDK declaration, enable `skipLibCheck`, or use a canary: rejected because each hides or assumes an unverified upstream compatibility fix.
- `@supabase/ssr`: deferred until a cookie-based UI session route exists; P02-03 uses explicit bearer validation and does not need another dependency.
- Service-role repository: rejected because it bypasses RLS and would make an application bug an ownership breach.

## Consequences and validation

No runtime dependency remains from the failed experiment; install and uninstall both completed and the lockfile returns to the existing dependency set. Run typecheck/lint/unit, client-secret/bundle boundary checks and real local Auth A/B integration. Errors are mapped to bounded application results and redacted. Adapter revert is the rollback before release.
