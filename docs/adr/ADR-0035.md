# ADR0035 — Groq ranks known candidates, deterministic planner keeps authority

2026-10-30, AI01/AI02. User authorized Smart Discovery after G4 approval; no live paid API authorization or credentials supplied.

Official review: [structured outputs](https://console.groq.com/docs/structured-outputs) supports strict schemas with required fields and closed objects; streaming/tools are excluded. [Models](https://console.groq.com/docs/models) currently lists `openai/gpt-oss-20b`/`openai/gpt-oss-120b` as production models; both support strict output. Require explicit configured model from this reviewed subset, no default model or deprecated fallback. [API](https://console.groq.com/docs/api-reference) supports max_completion_tokens and low reasoning effort for these models. Re-review availability/pricing before deployment, handle retirement/errors with deterministic fallback.

Use native fetch at fixed HTTPS chat-completions endpoint, one attempt and no SDK/retry dependency. Only bounded opaque IDs, canonical categories, coarse distance from city center and coarse optional preferences are sent. No user narrative, dates, addresses, coordinates/base or provider keys. Exclude request-only provider content. Output is an exact permutation of known IDs with a closed reason-code vocabulary; runtime validation rejects unknown/duplicate/missing IDs, facts, refusal, truncation and malformed responses. AI may choose a shortlist of additional suggestions; it never removes original selected/required/locked stops or supplies a schedule. Existing deterministic engine then routes/verifies, with separate candidate/apply confirmation.

Default OFF. Enabling requires key, reviewed model, explicit operator cost-control approval, ZDR confirmation, positive daily request/token/micro-USD caps, minute cap and current configured input/output prices. Reserve before dispatch and do not refund ambiguous failures. Input-byte and completion ceilings give conservative operational token/cost estimates; these are not a billing guarantee. [Rate limits](https://console.groq.com/docs/rate-limits) are organization-scoped; process accounting needs shared enforcement before distributed deployment. Configure and verify actual [organization spend limits](https://console.groq.com/docs/spend-limits) at G8.

[Data controls](https://console.groq.com/docs/your-data): default inference retention has reliability/abuse exceptions; organization ZDR is available. Operator confirmation is configuration, not proof of an actual account setting. Verify it before live use. No batches/files/tools, application prompt cache or response persistence; no keys, prompts or raw outputs in logs.

Alternatives rejected: AI-generated place facts/routes, unbounded retries, using an old hardcoded model, forwarding restricted provider data, or rewriting the tested planner. Fixture tests prove transport/contracts/fallback behavior only, not recommendation quality or paid account controls. No dependency/migration changes. Rollback disables adapter; existing deterministic no-key behavior remains. G5–G8 unchanged.

UI-B integration amendment: an explicit Brave opt-in may also return a bounded `transient` sibling of the exportable `data` envelope. This is view-only request content, never forwarded to AI or included in candidate draft, local save, owner apply or JSON export. Provider IDs are removed and source URLs stripped of query/fragment/credentials. Client holds it separately in memory, clears on actual input changes/page hide/visibility loss and after five minutes. Independent-entry action opens the existing manual pin flow without copying provider coordinates/facts into owned data. This enables inspecting a search result without laundering its storage rights. Earlier AI02-02 aggregate-only API evidence is historical; UI-B adds the segregated display contract and regression tests. Live use/terms/account controls still require the existing approvals and G8 review.
