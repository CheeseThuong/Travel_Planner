# ADR-0031 — Additive editorial discovery profiles

Correction evidence: first clean replay returned SQLSTATE22023 for JSON-null sources because PostgreSQL evaluated array length before the separate source-shape constraint. Retain the23514 assertion. Add forward migration `20261029000200_discovery_source_bounds.sql` with CASE-guarded array length; do not rewrite the first already locally applied migration. Invalid inputs remain rejected; no security errors or assertions are suppressed.

The first attempt of the forward correction failed before applying because a multi-column CHECK received PostgreSQL's table-level generated name `place_discovery_profiles_check`. Inspected actual `pg_constraint` definitions, corrected only the unapplied migration's DROP target, and retained the reset failure log. The replacement has an explicit stable constraint name.

Status: implementation detail under the user-approved G4/Discovery request2026-10-29. No new library, production or live-provider approval.

Preserve original places columns, UUIDs, source metadata and six legacy categories. Broaden only the category allowlist to include the ten canonical discovery groups. New lodging can use `lodging` directly, never a fabricated attraction category. Store richer optional data in a one-to-one `place_discovery_profiles` extension with a composite place/city foreign key. Multi-categories retain the parent category's canonical group; source arrays retain provider identity/license/retention. Unknown prices remain null; no AI or source inference supplies hours, access or prices.

Profiles are editorial data: no public/user write grants or security-definer write API. Public SELECT requires approved profile AND published place/city. Existing place reads/owner APIs retain their current policies. A scoped invoker trigger bootstraps only independently sourced OSM seed metadata into draft profiles; migration backfills existing eligible rows without changing any old place field/timestamp. Synthetic legacy rows without source metadata need no invented profile. New editorial data supplies its own validated profile.

Persistent source records accept open-license OSM/editorial or explicitly user-owned sources. Brave/Google request-only search content is excluded pending a reviewed retention policy. Brave's documented ephemeral POI IDs must not become permanent catalog keys. No search result cache or third-party image copying is introduced. Google Place ID-only references in the existing trip schema are unchanged.

Alternatives: replace old category values/IDs, put hotels under attraction, overwrite source metadata, expose authenticated editorial CRUD, silently persist provider results or mutate historical migrations (rejected). A profile extension avoids making unrelated trip/storage modules depend on new data. More joins are acceptable at the current bounded catalog size.

Verify migration on existing60 rows with before/after comparison, clean replay/seeding, array/null/cost/source constraints, category consistency, draft/approved publication, cross-city references and grants/RLS via pgTAP. Repeat original suites and real Auth. Rollback drops task-only trigger/functions/profile table; restore the old category allowlist only when no new-category records remain after a separately reviewed export/migration. Never delete such records merely to roll back.
