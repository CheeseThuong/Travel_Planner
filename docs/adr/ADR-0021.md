# ADR-0021 — Verify actual DB port binding and scope a Windows adapter

Status ACCEPTED corrective implementation detail,2026-10-22. P02-01 network verification reopened after host evidence; G1 unaffected, G2 not verified. No global Docker/firewall/PATH changes or production action.

The documented network host_binding_ipv4 option was present but actual Windows Docker29.8.2 published0.0.0.0/:: anyway. A separate sleep-only container reproduced this independently of Supabase. Explicit `127.0.0.1:host:container` produced only127.0.0.1. Therefore a network-option assertion alone is insufficient and previous loopback claims are superseded by this correction. Stack/probes were stopped; there was no real trip data or cloud database.

Keep the pinned Supabase CLI/image and all DB tests. On Windows only, scope a Docker forwarding adapter to the Supabase child's PATH. For this project's named containers/network and reserved35320..35329 ports, require/insert an explicit127.0.0.1 in publish arguments; reject foreign scopes/IPs. Other Docker commands pass through to an absolute real Docker path resolved before adding the adapter. Never change global PATH or intercept unrelated user shells. After every successful start, inspect actual DB/gateway published bindings; stop and fail if any address is not loopback. Linux uses native Docker plus the same actual binding check.

Build a small repository-owned C# console adapter with the already-installed .NET10 SDK10.0.401 on this host. Use only BCL, no NuGet packages, an offline source-cleared NuGet config, ignored .tools build/cache output and telemetry disabled. .NET runtime is [MIT](https://github.com/dotnet/runtime/blob/main/LICENSE.TXT); no application dependency or client bytes. Windows local DB development now requires the .NET10 SDK; no toolchain is installed globally by this task. [ProcessStartInfo.ArgumentList](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.argumentlist) forwards arguments without a shell or manual quoting, preserving secret-bearing Docker args without logging them.

Tests: argument transforms/rejections, exact passthrough of quotes/backslashes/metacharacters without executing a shell, compiler/self-test on Windows, actual published binding checks with fail-closed cleanup, then full actual reset/pgTAP110 twice. Initial private SQL test failed at GRANT USAGE ON SCHEMA pg_temp (zero68 assertions ran); resolve the actual temporary namespace via pg_my_temp_schema, keeping all68 assertions unchanged. Retain failure logs and rerun. P02-01 returns DONE only after actual binding evidence; P02-02 depends on that correction.

Actual correction evidence: forwarding without explicit byte-stream relay lost Docker stderr and failed container inspection; a new end-to-end test reproduced it. Explicit asynchronous stdin/stdout/stderr relay now preserves UTF8, quotes, metacharacters and exit status with no shell. Windows local stack then started/reset successfully, actual DB35322 and gateway35321 both bound127.0.0.1. Later private tests add2 narrow UID-helper checks (112 total). Temp-schema GRANT was proven a no-op warning and unnecessary for the same session, so remove the setup statement while preserving every assertion. Actual clean replay passes; no warning filter or test skip.

Alternatives: trusting config alone disproven; changing daemon defaults affects other projects; downgrading or binary-patching CLI rejected; skipping network checks rejected. Rollback removes only the adapter/source/tooling output and leaves the host stack stopped if safe binding is unavailable. Preserve all source catalogs, data and prior security tests.
