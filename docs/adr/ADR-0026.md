# ADR-0026 — Deterministic local-day feasibility conventions

Status: ACCEPTED implementation detail under the user's P04 engineering request after G3 PASS,2026-10-28.

Use integer local-day minutes and strict calendar dates for the currently supported Asia/Ho_Chi_Minh destinations. No instant conversion or DST support is inferred for new cities; the draft validator rejects unsupported destination/timezone combinations. Start/end are intersected with daily and edge-day bounds. A day with no activity window remains present with zero available minutes. Lunch starts at12:00 and is clipped to the day; `rest_buffer_minutes` is a separate between-visit buffer, not misrepresented as provider travel duration. Return-to-base travel is reserved when requested.

Weekly opening intervals are half-open, allow end24:00 and split overnight carry into the next local day; equal start/end is invalid (use00:00–24:00 for all day). An empty verified interval list means closed. Verified hours require nonempty source and a parseable checked_at no later than injected Clock.now(); no global clock. Weekly hours do not encode holiday exceptions and emit HOURS_HOLIDAYS_UNVERIFIED; unknown hours emit HOURS_UNVERIFIED and tentative feasibility, never verified opening claims. No arbitrary freshness expiry is invented.

Locks retain their date, exact start and zero-based absolute stop position. Conflicts are reported; no lock is moved, dropped or reclassified as an unlocked optional point. Calendar checks bounds/hours/breaks/overlap/order; matrix travel checks follow in the planner. If constraints conflict, no feasible candidate may be applied.

Alternatives: guessed hotel/start times or treating missing hours as verified open (rejected); host-local Date arithmetic (rejected); full DST/timezone dependency before adding a supported DST city (deferred). Unit fixtures fix the clock/date/matrix; test split hours, overnight carry, closed/unknown, edge days and conflicting locks. Rollback task code; no DB/API migration or package addition.
