# ADR-0028 — Feasible candidates, immutable locks and soft budget guidance

Status: ACCEPTED implementation detail for requested P04 after G3 PASS,2026-10-28.

Pure scheduling consumes a validated draft, prepared directed matrix and injected fixed Clock/runID/seed. Day feasibility computes whole-minute travel/rest/wait, uninterruptible travel and visits outside mandatory breaks, verified opening windows and optional return to base. Tentative hours/access/approximate provenance remain explicit. Cap relaxed2/balanced3/active4 visits/day, matching the wizard guidance and staying below baseline8. Reject manual-transfer automation and report UNREACHABLE with MANUAL_TRANSFER_REQUIRED. No geographic road/boat access is inferred from distance.

Initialize immutable locks, insert required before optional across all days/positions, use earliest closing constraint and stable ID ties, geographic farthest-first seed clusters as soft day affinity, then accept only feasible within-day directed2-opt improvement. This is a bounded deterministic heuristic, not a proof of globally maximal service. Recompute directed edges after every reversal. Lock positions are absolute zero-based indices; provisional insertion may fill preceding slots but never push a lock past its index. Unfilled final lock positions or other lock conflict block candidate creation; input remains untouched and every selection remains explicitly accounted for in the conflict result. No invalid candidate may be applied.

Budget is soft because no existing hard-budget preference exists. Required/locked stops are not discarded due to cost. Optional ordering prefers known affordable/lower costs, then uncertainty/over-budget guidance; capacity/time infeasibility receives the existing reason enum. Scheduled cost summary preserves unknown costs and over-budget/incomplete flags. Do not invent BUDGET as a DB reason or silently make the existing budget a hard constraint.

Generate rejects manual mode. Manual assignments are validated as entered (including conflicts, unassigned IDs, bounds, hours, directed travel, breaks, return and locks); return order/date/time unchanged. EngineCandidate extends the existing in-memory candidate with score/budget/diagnostics/break/return metadata; no persistence/schema change. RunID is supplied by orchestration; the domain creates no random IDs or wall-clock timestamps.

Alternatives: nearest-neighbor alone, symmetrized2-opt, moving locks, silent omission or optimization in manual mode (rejected); exact combinatorial optimum and unsupported boat/overnight tours (deferred). Tests cover13 Master edge cases, deterministic/accounting/immutability invariants and budget/lock conflicts. Rollback task-only code/types/tests; P04-04 must separately validate public inputs/auth/versioned apply and persistence policy.
