# ADR-0011 — Resolve baseline scope and contract ambiguities
Status: ACCEPTED — user approved all four clarifications in chat on 2026-10-21.
Task: P00-01 follow-up; decisions SCOPE-001, API-001, API-002, ENGINE-001.

## Context
Master 2.2 duplicated must-visit under P1 despite P0 engine requirements. Endpoint inventory used 400 for semantic validation but T-002/T-003 require 422. Sitemap described client token decryption despite opaque server hash resolution. Overnight hours and overnight/boat tours were conflated.

## Decision
- Required/optional selection and required-first planning are P0; advanced pace/meal/distance preferences remain P1.
- Malformed JSON is 400 VALIDATION_ERROR; structurally/semantically invalid parsed JSON is 422 VALIDATION_ERROR. Endpoint inventory and tests must agree.
- Client parses URL fragment and POSTs opaque share token; server resolves hash and returns sanitized view. No client trip decryption contract.
- Normalize opening intervals crossing midnight; split visits into permitted local-day windows. MVP does not automatically schedule overnight/boat tours or invent car routes to islands. Unsupported transfer needs explicit warning/manual handling or unscheduled reason. No weakening of trip local-day bounds.

## Alternatives and trade-offs
Deferring required-first would contradict engine P0. Keeping mixed status codes makes contract tests ambiguous. Encrypted client trip sharing would require a new architecture. Boat/overnight tour optimization requires transport/time constraints beyond baseline. These conservative clarifications keep existing architecture while making acceptance testable.

## Updated validation cases
- P03 selection/required flags; P04 required-impossible accounting and priority invariants.
- Contract tests: malformed JSON ->400; valid JSON with invalid dates/31 points/schema violations ->422; auth/ownership status unchanged.
- P06 fragment parsing/POST resolution, no token in query/log, sanitized payload and unauthorized mutation tests.
- P04 split/overnight hours, partial-day bounds, unsupported boat transfer; do not infer physical reachability from coordinates alone.

Revert affected Master wording and mark four decisions unresolved; G0 cannot pass until resolved again. No runtime/schema migration exists.
