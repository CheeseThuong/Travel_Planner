# ADR-0027 — Approximate routing, directed validation and honest usage

Status: ACCEPTED implementation detail for requested P04 after G3 PASS,2026-10-28.

Routing uses existing ports, no new SDK. Validate unique IDs/coordinates,31-node maximum (30 selected plus base), exact node order/dimensions and integer nonnegative directed durations/provenance. Keep unreachable distinct. Approximate fallback computes great-circle distance, a1.3 distance factor, and heuristic speeds walk4/motorbike25/drive30km/h, rounded up to whole minutes, with high uncertainty. These are configurable only by code/ADR, not claimed as measured routes/traffic/access. Engine must separately reject manual transfers and warn for unverified access. No provider cache or persistence.

A bounded adapter makes at most one injected primary call with a1500ms default deadline (maximum5000ms) and caller abort. Invalid/failed/timed-out primary falls back; caller cancellation propagates. Node/element cap is checked before calling. No live Google adapter is enabled or implemented in this task; budgeted live integration remains opt-in staging work. Do not invent a primary's usage after failure: widen MatrixResult.elements_requested to `number | null` (null means unknown), emit PROVIDER_USAGE_UNKNOWN and conservatively treat the full bounded matrix as reserved by callers. Success reports the supplied bounded measured count; no request bodies/errors/URLs are retained.

Alternatives: silently symmetrize matrices, replace unreachable with straight-line travel, zero failed provider usage, use raw ETA claims or retry without bounds (rejected). New live Google credentials/SDK/paid calls (deferred; no user key/budget/deployment approval). Tests cover directed identity, malformed cells, no-key/equal-coordinate fallback, size limits,429/timeout/caller abort and unknown usage. Rollback task port/code/test changes; no DB/schema/API migration.
