# ADR-0015 — Scoped lint patch and user-requested local motion demo
Status: ACCEPTED scope under current explicit user request (2026-10-21); implementation/gates remain evidence-based. No production authorization.

## Context
User requested actual fixes, an opened performance demo, Three.js/GSAP/Motion Design skills. The replacing AGENTS instructions preserve gates. Upstream braces still has no patch and ESLint9 is EOL; upstream React/import/a11y plugin peers still exclude10. A blind alias from fast-glob to tinyglobby changes root scanning behavior.

## Decision
Vendor the published Next16.4.2 ESLint plugin with original version/checksums/MIT notice and every rule/export/config unchanged. Patch only its get-root-dirs helper and dependency to tinyglobby0.2.17. Bound pathological glob nesting/length, preserve directory scanning semantics with positive and negative tests. Scoped npm override selects this actual source patch; it is not an advisory suppression or a fake upstream version bump. Vendored third-party distribution is excluded from application style lint just like node_modules; helper behavior and rule/config integrity have dedicated regression tests. Application lint coverage remains unchanged. Remove the fork when an audited upstream fix matches behavior.

ESLint9 EOL is a separate unresolved support issue. Do not claim it fixed by removing braces or silently weaken ADR0014. G1 cannot pass without resolving/explicitly reviewing support and all remaining baseline tasks/CI. No core phase progression while G1 is unverified/failing.

Create independent Phase01 P01-05 preview extension under the user's explicit request. Skills/research can run in parallel; motion app demo begins only after actual patch tests/audit/static/build checks pass. This limited decorative preview is not P07 completion or permission for P02+ work. Original single-city planner/persistence/share contracts unchanged.

## Animation and performance boundaries
- Three0.186.1 MIT, GSAP3.15.0 standard no-charge license, Motion14.4.0 MIT; @types/three0.186.0 MIT dev-only. GSAP is not MIT; reviewed ordinary travel UI use, no visual-animation-builder product or library relicensing.
- Dynamic Three import only after user activates optional3D; SVG remains fallback and all text/links work without canvas/JS. Cap DPR1.5, simple owned geometry/materials, no external models/textures, pause hidden/offscreen, stop/dispose/context loss/unmount. Reduced motion and low capability prevent starting animation. No core layout shifts.
- GSAP owns scoped decorative reveal; Motion owns small control/card interactions; Three owns canvas only. Do not animate same transform from multiple engines; retain keyboard focus/native links and reduced-motion branch.
- Playwright1.64.1 Apache2 + Lighthouse13.5.0 Apache2 for local real-browser checks; no production tests or remote provider requests. Measure production build, record browser/viewport/throttling/conditions/results/screenshot artifacts and limitations.
- Skills: install official GSAP skills after source review; create missing focused Three.js/Motion Design skills via skill-creator, validate/read/apply them. No automatic permission expansion from installed instructions.

## Alternatives / trade-offs
Waiting alone does not satisfy the request. Removing Next/React lint checks or forcing audit downgrade is rejected. Whole-stack migration/canary/peer-ignore rejected. Small auditable vendor fork increases maintenance but changes one helper and removes actual vulnerable code from dependency graph. Early decorative preview adds bundle/GPU cost; explicit lazy activation/fallback limits impact. Full visual/performance approval remains G7.

## Validation / rollback
Before/after enabled rule config + upstream rule file hashes; invalid Next/React/hooks/a11y/TS fixtures; glob strings/arrays/braces/globstar/absolute/Windows/missing/deep patterns; full audit and dependency tree; typecheck/lint/build/content/HTTP smoke. Demo browser normal/mobile/reduced-motion/no-WebGL/no-JS/stop/restart/visibility; Lighthouse three routes with recorded conditions. Rollback fork/override/lock or remove motion components/deps to static fallback without touching trip data. No schema migration.
